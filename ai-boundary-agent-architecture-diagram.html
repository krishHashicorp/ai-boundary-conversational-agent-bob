WatsonX + HCP Boundary AI Agent

Architecture reference — components, data flows, session lifecycle, and design decisions

System Diagram

blue — REPL / agent loop purple — LLM / WatsonX orange — Boundary / proxy green — SSH / execution

Components

main.py
Terminal REPL. Displays [connected ✓] / [disconnected] prompt status. Registers atexit cleanup to close SSH and Boundary on any exit path.
agent.py
ReAct loop — up to 10 reasoning steps. Parses LLM JSON output, dispatches tool calls, feeds observations back. Exposes 4 tools: connect_to_host, run_command, check_connection_status, disconnect_from_host.
watsonx_llm.py
Thin SDK wrapper. Uses /ml/v1/text/chat (not deprecated generate_text). Model lazily initialised and cached. Prepends system message if absent.
boundary_session.py
Authenticates via password or OIDC, spawns boundary connect as a long-lived subprocess, parses proxy JSON (address, port, injected credentials), keeps process alive for the session.
ssh_exec.py
Opens paramiko.Transport to the Boundary proxy port. Uses auth_none() (Boundary handles credential injection). Requests PTY, invokes interactive shell, clears PROMPT_COMMAND. All run_command() calls reuse the same shell — shell state (cwd, env vars) persists between turns. Output delimited by unique sentinel + exit-code capture.

Session Lifecycle

1
User runs python main.py — prompt shows [disconnected]
↓
2
User says "Connect to the host" — agent calls connect_to_host
↓
3
boundary_session.authenticate() — sends credentials to HCP Boundary, stores BOUNDARY_TOKEN in env
↓
4
boundary_session.connect(target_id) — spawns proxy, parses JSON, extracts injected SSH credentials
↓
5
ssh_exec.connect(host, port) — Transport + auth_none() + PTY + invoke_shell()
↓
6
Prompt shows [connected ✓] — all subsequent commands reuse this shell
↓
N
Each run_command() sends over stdin, reads until prompt, parses sentinel for exit code. Shell state persists.
↓
D
User says "Disconnect" — ssh_exec.disconnect() closes channel + transport, boundary_session.disconnect() terminates proxy process

2

Browser opens → IBM Verify login → MFA → token returned

Credential Injection Flow

1
SSH username + password stored in HCP Boundary Credential Store — bound to the SSH target
↓
2
boundary connect -target-id=tssh_... JSON response includes injected credentials:
"credentials": [{"credential": {"username": "...", "password": "..."}}]
↓
3
Credentials extracted ephemerally — passed to ssh_exec.connect(), never written to disk or logged
↓
4
paramiko.Transport.auth_none(username) — Boundary proxy accepts anonymous auth, injects credentials at the Worker layer
↓
5
Agent connects to Ubuntu as the correct user — SSH password never held statically by the agent

Key Design Decisions

Persistent shell over exec_command Preserves cwd and env vars between commands. Boundary session recording captures one continuous interactive session, not discrete exec calls.
auth_none for SSH Boundary proxy handles credential injection at the Worker layer and accepts anonymous auth. Standard SSHClient tries password/key auth by default and fails.
Sentinel-based output delimiting Shell prompts vary in shape. A unique UUID sentinel echoed with the exit code gives a deterministic end-of-output marker regardless of prompt format.
PROMPT_COMMAND='' after connect Cloud VM images print instance metadata via PROMPT_COMMAND before every prompt. Clearing it keeps LLM input free of noise.
boundary connect not boundary connect ssh The raw connect command emits proxy address/port as JSON and stays alive. The ssh subcommand launches a client directly — not suitable for paramiko.
SDK model.chat() not generate_text() The chat API handles prompt formatting per-model automatically. generate_text() requires manual chat templates and is deprecated.
